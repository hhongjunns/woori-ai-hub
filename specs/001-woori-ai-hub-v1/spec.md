# Feature Specification: Woori AI Hub V1 웹 서비스

**Feature Branch**: `001-woori-ai-hub-v1`

**Created**: 2026-08-22

**Status**: Draft

**Input**: User description: "Woori AI Hub의 V1 웹 서비스를 정의해줘. Woori AI Hub는 사내 임직원이 업무에 필요한 AI 서비스와 업무 지식을 하나의 웹 플랫폼에서 사용할 수 있도록 하는 AI 업무지원 플랫폼이다. V1에서는 실제 AI 기능을 구현하지 않고 웹 UI/UX 구현에 집중한다. 실제 LLM, RAG, Agent, MCP, 사내 DB 연동은 이후 단계에서 구현한다. 주요 화면: 1) Dashboard, 2) 코딩자동화, 3) 담당자 찾기, 4) 업무도우미, 5) 모니터링. UI/UX는 별도의 Figma 디자인을 Source of Truth로 사용한다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Dashboard에서 주요 서비스 한눈에 확인 (Priority: P1)

사내 임직원이 Woori AI Hub에 접속하면 Dashboard 화면에서 플랫폼이 제공하는
주요 AI 서비스와 업무도우미, 개발자동화 도구를 한눈에 확인하고, 그중
자주 사용하는 항목에 빠르게 접근할 수 있다.

**Why this priority**: Dashboard는 모든 사용자가 가장 먼저 마주하는
진입점이자 다른 모든 화면(코딩자동화, 담당자 찾기, 업무도우미,
모니터링)으로 이동하는 허브 역할을 한다. Dashboard가 없으면 나머지
화면 자체를 사용자가 발견할 수 없으므로 최우선 순위를 가진다.

**Independent Test**: Woori AI Hub에 접속하여 Dashboard가 표시되는지,
주요 AI 서비스 목록과 자주 사용하는 업무도우미/개발자동화 도구
바로가기가 노출되고 각 항목 클릭 시 해당 화면으로 이동하는지 확인하는
것으로 독립적으로 테스트 가능하다.

**Acceptance Scenarios**:

1. **Given** 사용자가 Woori AI Hub에 접속한 상태, **When** Dashboard
   화면이 로드되면, **Then** Woori AI Hub가 제공하는 주요 AI 서비스
   목록(코딩자동화, 담당자 찾기, 업무도우미, 모니터링 등)이 한 화면에
   표시된다.
2. **Given** Dashboard 화면, **When** 사용자가 자주 사용하는 업무도우미
   또는 개발자동화 도구 항목을 클릭하면, **Then** 해당 도구/화면으로
   이동한다.
3. **Given** Dashboard 화면, **When** 사용자가 특정 AI 서비스 카드를
   클릭하면, **Then** 해당 서비스의 상세 화면으로 이동한다.

### User Story 2 - 업무도우미로 업무 시스템 정보 탐색 (Priority: P1)

사내 임직원이 담당 업무 시스템(예: DM관리시스템)에 대한 정보가 필요할
때, 업무도우미 화면에서 해당 시스템을 선택하고 담당자, 솔루션 정보,
서버/DB 정보, 주요 배치, 인터페이스, 운영 정보, 관련 문서를 구조화된
형태로 탐색할 수 있다.

**Why this priority**: 업무도우미는 Woori AI Hub의 핵심 차별점인 "하나의
플랫폼에서 업무 지식을 탐색"하는 기능을 대표하며, 지식그래프 형태의
정보 탐색이 이 기능의 핵심 포인트로 명시되었다. Dashboard와 함께 V1의
핵심 가치를 가장 직접적으로 보여주는 화면이다.

**Independent Test**: 업무도우미 화면에서 DM관리시스템을 선택한 뒤,
담당자/솔루션 정보/서버·DB 정보/주요 배치/인터페이스/운영 정보/관련
문서 각 항목을 조회할 수 있는지 확인하는 것으로 독립적으로 테스트
가능하다.

**Acceptance Scenarios**:

1. **Given** 업무도우미 화면, **When** 사용자가 업무 시스템 목록에서
   "DM관리시스템"을 선택하면, **Then** 해당 시스템의 업무 정보 탐색
   화면으로 이동한다.
2. **Given** DM관리시스템 정보 탐색 화면, **When** 사용자가 담당자
   정보를 조회하면, **Then** 해당 시스템의 담당자 정보(이름, 역할 등)가
   표시된다.
3. **Given** DM관리시스템 정보 탐색 화면, **When** 사용자가 솔루션
   정보, 서버/DB 정보, 주요 배치, 인터페이스, 운영 정보, 관련 문서 중
   하나를 선택하면, **Then** 해당 정보가 구조화된 형태로 표시된다.
4. **Given** DM관리시스템 정보 탐색 화면, **When** 사용자가 정보 항목
   간의 연관 관계(예: 담당자 ↔ 솔루션 ↔ 서버/DB)를 확인하려 하면,
   **Then** 항목 간 관계를 인터랙티브 지식그래프(노드/엣지, 확대/축소
   가능)로 파악할 수 있다.
5. **Given** 지식그래프가 표시된 화면, **When** 사용자가 특정 노드(예:
   담당자 노드)를 클릭하면, **Then** 해당 항목의 상세 정보가 별도
   패널에 표시된다.

### User Story 3 - 코딩자동화 작업 카드 워크플로 (Priority: P2)

사내 개발자 임직원이 코딩자동화 화면에서 레포지토리를 선택하고 자연어로
새 작업을 요청하면, (V1 기준 Mock) AI가 작업 카드를 생성한다. 사용자는
생성된 카드를 실행 대기열(진행중/대기/완료)에 올리고, 진행중인 카드를
선택해 분석→설계→코딩/테스트→PR 생성으로 이어지는 실행 타임라인과
진행 로그를 확인하며, 추가 지시를 댓글로 남길 수 있다.

**Why this priority**: 개발 생산성 도구는 핵심 사용자군(개발자)에게
중요한 가치이지만, Dashboard/업무도우미 대비 이용 대상이 제한적이므로
P2로 분류한다. (Figma 레퍼런스 검토 결과 실제 디자인은 단순 목록이
아닌 작업 카드 워크플로임을 확인하여 V1 범위를 이에 맞게 확장했다 —
2026-08-22, `/speckit-implement` 단계에서 사용자 확인.)

**Independent Test**: 코딩자동화 화면에서 레포지토리를 선택하고 새 작업
요청을 "카드로 변환"한 뒤 "이 카드로 실행"으로 진행중 컬럼에 올리고,
해당 카드를 선택해 실행 타임라인과 로그가 표시되는지 확인하는 것으로
독립적으로 테스트 가능하다.

**Acceptance Scenarios**:

1. **Given** 사용자가 코딩자동화 화면에 진입한 상태, **When** 화면이
   로드되면, **Then** 레포지토리 목록, 새 작업 요청 입력 폼, 진행중/대기/완료
   3개 컬럼의 작업 카드 목록이 표시된다.
2. **Given** 코딩자동화 화면, **When** 사용자가 레포지토리를 선택하고 새
   작업 요청을 입력한 뒤 "카드로 변환"을 누르면, **Then** 실제 AI 처리
   없이 미리 정의된 Mock 작업 카드(제목/설명/완료 조건/우선순위 포함)가
   미리보기로 표시된다.
3. **Given** 작업 카드 미리보기가 표시된 상태, **When** 사용자가 "이
   카드로 실행"을 누르면, **Then** 해당 카드가 진행중 컬럼에 추가된다.
   **When** 대신 "다시 요청하기"를 누르면, **Then** 미리보기가 초기화되고
   새 작업 요청을 다시 입력할 수 있다.
4. **Given** 진행중 컬럼에 카드가 있는 화면, **When** 사용자가 카드를
   선택하면, **Then** 해당 카드의 실행 상세 패널에 분석→설계→코딩/
   테스트→PR 생성 4단계 타임라인과 각 단계의 완료 로그(상대 시각 포함)가
   표시된다.
5. **Given** 실행 상세 패널이 열린 상태, **When** 사용자가 댓글(추가
   지시)을 입력하고 제출하면, **Then** 댓글이 로그 영역에 추가로
   표시된다(Mock, 실제 작업에 반영되지는 않음).

### User Story 4 - 담당자 찾기 질의 (Priority: P2)

사내 임직원이 채팅형 화면에서 자연어로 업무 관련 질문을 입력하면,
질문에 대한 (V1 기준 Mock) 답변을 확인할 수 있고, 이전에 주고받은
질문과 답변이 대화 이력으로 화면에 계속 남아 있어 여러 질문을 이어서
할 수 있다.

**Why this priority**: 자연어 질의 경험은 향후 RAG 기반 기능으로
발전할 핵심 기능이지만, V1에서는 Mock Response만 제공되므로 실제 업무
가치는 제한적이다. UI/UX 검증 목적의 기능으로 P2로 분류한다.

**Independent Test**: 담당자 찾기 화면에서 임의의 질문을 입력하고
제출했을 때 Mock 답변이 화면에 표시되는지 확인하는 것으로 독립적으로
테스트 가능하다.

**Acceptance Scenarios**:

1. **Given** 담당자 찾기 화면, **When** 사용자가 자연어로 업무 관련
   질문을 입력하고 제출하면, **Then** 미리 정의된 Mock 답변이 채팅
   메시지 형태로 화면에 추가된다.
2. **Given** 이미 하나 이상의 질문/답변을 주고받은 담당자 찾기 화면,
   **When** 사용자가 새로운 질문을 입력하고 제출하면, **Then** 새
   질문과 답변이 기존 대화 이력 아래에 이어서 표시되고 이전 대화
   내용은 화면에서 사라지지 않는다.
3. **Given** 담당자 찾기 화면, **When** 사용자가 질문을 입력하지 않고
   제출을 시도하면, **Then** 질문 입력이 필요하다는 안내가 표시된다.

### User Story 5 - 모니터링 현황 확인 (Priority: P3)

사내 임직원이 모니터링 화면에서 Woori AI Hub가 제공하는 AI
서비스/업무도우미 자체의 가동 현황(서비스별 상태, 응답 지연 여부 등)을
확인할 수 있다.

**Why this priority**: 모니터링은 운영 지원 성격의 화면으로, V1의
핵심 가치(AI 서비스/업무 지식 탐색)에 비해 상대적으로 부가적인
기능이므로 P3로 분류한다.

**Independent Test**: 모니터링 화면에 진입해 상태 정보가 표시되는지
확인하는 것으로 독립적으로 테스트 가능하다.

**Acceptance Scenarios**:

1. **Given** 사용자가 모니터링 화면에 진입한 상태, **When** 화면이
   로드되면, **Then** Woori AI Hub가 제공하는 AI 서비스/업무도우미
   각각의 현재 가동 상태가 표시된다.
2. **Given** 모니터링 화면, **When** 특정 AI 서비스/업무도우미의 상태가
   정상이 아닌 경우, **Then** 해당 항목이 시각적으로 구분되어
   표시된다.

---

### Edge Cases

- 업무도우미에서 사용자가 선택할 수 있는 업무 시스템이 DM관리시스템
  하나뿐일 때, 목록/선택 UI는 어떻게 동작하는가? (V1은 예시로
  DM관리시스템 한 건만 제공)
- 담당자 찾기에서 사용자가 동일한 질문을 반복 입력하거나, 매우 길거나
  의미 없는 텍스트를 입력하면 어떻게 되는가?
- 코딩자동화 도구 중 상태가 "점검 중" 등 비정상 상태인 도구를
  사용자가 클릭하면 어떻게 되는가?
- Dashboard에 표시할 "자주 사용하는" 항목이 아직 없는 신규 사용자의
  경우 무엇이 표시되는가?
- 네트워크 지연 등으로 화면 로드가 지연될 때 사용자에게 어떤 대기
  상태가 표시되는가?

## Requirements *(mandatory)*

### Functional Requirements

**공통**

- **FR-001**: 시스템은 Dashboard, 코딩자동화, 담당자 찾기, 업무도우미,
  모니터링 5개 화면 간에 일관된 방식(공통 헤더/내비게이션)으로 이동할
  수 있어야 한다.
- **FR-002**: V1의 모든 화면은 실제 사내 시스템/DB와 연동하지 않고
  Mock Data를 사용하여 콘텐츠를 표시해야 한다.
- **FR-003**: 시스템은 Figma 디자인 레퍼런스에 정의된 레이아웃,
  컴포넌트, Typography, 색상, 간격을 화면별로 그대로 반영해야 한다.

**Dashboard**

- **FR-010**: 시스템은 Dashboard에서 Woori AI Hub가 제공하는 주요 AI
  서비스 목록을 표시해야 한다.
- **FR-011**: 시스템은 Dashboard에서 사용자가 자주 사용하는 업무도우미
  및 개발자동화 도구에 대한 바로가기를 제공해야 한다.
- **FR-012**: 시스템은 Dashboard의 각 서비스/도구 항목을 클릭하면 해당
  화면으로 이동시켜야 한다.

**코딩자동화**

- **FR-020**: 시스템은 코딩자동화 화면에서 레포지토리 목록을 사이드바에
  표시하고 선택할 수 있어야 한다.
- **FR-021**: 시스템은 선택된 레포지토리에 대해 새 작업을 자연어로
  요청할 수 있는 입력 폼("새 작업 요청")을 제공해야 한다.
- **FR-022**: 사용자가 "카드로 변환"을 누르면 시스템은 실제 AI 처리
  없이 미리 정의된 Mock 작업 카드(제목, 설명, 완료 조건, 우선순위
  포함)를 생성해 미리보기로 표시해야 한다.
- **FR-023**: 시스템은 미리보기 카드에 대해 "이 카드로 실행"(진행중
  컬럼에 추가) 및 "다시 요청하기"(미리보기 초기화) 동작을 제공해야
  한다.
- **FR-024**: 시스템은 작업 카드를 진행중/대기/완료 3개 컬럼으로 구분해
  표시해야 하며, 각 카드에는 레포지토리, 제목, 우선순위가 표시되어야
  한다.
- **FR-025**: 시스템은 진행중 컬럼의 카드를 선택하면 해당 카드의 실행
  상세 패널을 표시해야 한다. 패널에는 분석→설계→코딩/테스트→PR 생성
  4단계 실행 타임라인과 각 단계의 완료 로그(상대 시각 포함)가 포함된다.
- **FR-026**: 시스템은 실행 상세 패널에서 사용자가 댓글(추가 지시)을
  입력해 로그에 추가할 수 있는 UI를 제공해야 한다(Mock, 실제 작업에는
  반영되지 않음).

**담당자 찾기**

- **FR-030**: 시스템은 담당자 찾기 화면에서 사용자가 자연어 텍스트로
  업무 관련 질문을 입력할 수 있는 입력 UI를 제공해야 한다.
- **FR-031**: 시스템은 사용자가 질문을 제출하면 실제 AI 응답 대신
  미리 정의된 Mock Response를 표시해야 한다.
- **FR-032**: 시스템은 담당자 찾기 화면의 질의/응답 구조를 향후 실제
  RAG 기반 업무 질의 기능으로 교체할 수 있도록, 질의 입력과 응답
  표시 영역이 분리된 구조로 설계해야 한다.
- **FR-033**: 담당자 찾기는 채팅형(Chat) 인터페이스로 동작해야 하며,
  사용자가 여러 질문을 이어서 입력할 수 있도록 이전 질문과 Mock
  답변으로 구성된 대화 이력을 화면에 누적하여 표시해야 한다.

**업무도우미**

- **FR-040**: 시스템은 업무도우미 화면에서 업무 시스템 목록(V1 예시:
  DM관리시스템)을 표시하고 선택할 수 있어야 한다.
- **FR-041**: 시스템은 선택된 업무 시스템에 대해 담당자, 솔루션 정보,
  서버/DB 정보, 주요 배치, 인터페이스, 운영 정보, 관련 문서 정보를
  각각 조회할 수 있어야 한다.
- **FR-042**: 시스템은 업무 정보 항목(담당자, 솔루션 정보, 서버/DB
  정보, 주요 배치, 인터페이스, 운영 정보, 관련 문서) 간의 연관 관계를
  노드-엣지 기반의 인터랙티브 지식그래프로 탐색할 수 있게 해야 한다.
  사용자는 그래프를 확대/축소하고 배치를 조정할 수 있어야 하며, 특정
  노드를 클릭하면 해당 항목의 상세 정보를 별도 패널에서 확인할 수
  있어야 한다.
- **FR-043**: 시스템은 업무도우미의 정보 탐색 화면 구조를 향후 AI
  Chat 기능을 추가로 연결할 수 있도록, 정보 표시 영역과 별도의 확장
  가능한 영역을 고려한 구조로 설계해야 한다. (V1에서는 실제 AI Chat
  기능을 구현하지 않는다.)

**모니터링**

- **FR-050**: 시스템은 모니터링 화면에서 모니터링 대상 항목의 현재
  상태를 표시해야 한다.
- **FR-051**: 시스템은 상태가 비정상인 항목을 정상 항목과 시각적으로
  구분하여 표시해야 한다.
- **FR-052**: 모니터링 화면은 각 업무 시스템의 서버/DB 등 인프라
  상태가 아니라, Woori AI Hub가 제공하는 AI 서비스 및 업무도우미
  자체의 가동 현황(서비스별 상태, 응답 지연 여부 등)을 대상으로
  한다.

### Key Entities

- **AI 서비스 (AI Service)**: Woori AI Hub가 제공하는 서비스 단위.
  이름, 설명, 카테고리(예: 업무도우미/개발자동화), 상태, 접근 링크를
  가지며 Dashboard 화면에서 사용된다.
- **레포지토리 (Repository)**: 코딩자동화에서 새 작업 요청의 대상이 되는
  코드 저장소. 이름을 가진다.
- **작업 카드 (Task Card)**: 코딩자동화의 작업 단위. 제목, 소속
  레포지토리, 설명, 완료 조건, 우선순위, 상태(진행중/대기/완료), 실행
  타임라인(분석/설계/코딩·테스트/PR 생성 4단계, 각 단계의 상태와 완료
  로그), 댓글 목록을 가진다.
- **업무 시스템 (Work System)**: 업무도우미가 탐색 대상으로 삼는 사내
  업무 시스템 단위(V1 예시: DM관리시스템). 시스템명과 하위 정보
  항목들을 가진다.
- **업무 정보 항목 (Work Info Item)**: 담당자, 솔루션 정보, 서버/DB
  정보, 주요 배치, 인터페이스, 운영 정보, 관련 문서 등 업무 시스템에
  속한 세부 정보 카테고리. 업무 시스템 및 서로 다른 정보 항목 간
  연관 관계(지식그래프의 노드/관계)를 가진다.
- **담당자 (Person in Charge)**: 특정 업무 시스템 또는 정보 항목과
  연결된 사람. 이름, 역할/소속 등의 속성을 가진다.
- **질의/응답 (Query & Mock Response)**: 담당자 찾기에서 사용자가
  입력한 질문과 이에 대응하는 미리 정의된 Mock 답변 쌍. 여러 쌍이
  하나의 대화 이력을 구성한다.
- **모니터링 항목 (Monitoring Item)**: 모니터링 화면에 표시되는 대상
  단위로, Woori AI Hub가 제공하는 AI 서비스/업무도우미 각각에
  대응한다. 이름, 상태(정상/비정상 등)를 가진다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자는 Woori AI Hub 접속 후 Dashboard에서 별도 안내
  없이도 주요 AI 서비스 목록을 즉시(추가 클릭 없이) 확인할 수 있다.
- **SC-002**: 사용자는 Dashboard에서 자주 사용하는 업무도우미 또는
  개발자동화 도구에 2회 이하의 클릭으로 도달할 수 있다.
- **SC-003**: 사용자는 코딩자동화 화면에서 레포지토리 선택부터 작업
  요청 입력, 카드 생성, 진행중 컬럼 확인까지 화면 전환 없이 한 화면
  안에서 완료할 수 있다.
- **SC-004**: 사용자는 담당자 찾기에서 질문을 제출한 직후(별도 로딩
  대기 없이) 화면 전환 없이 Mock 답변을 확인할 수 있다.
- **SC-005**: 사용자는 업무도우미에서 DM관리시스템을 선택한 뒤 3회
  이하의 클릭/이동으로 담당자, 솔루션 정보, 서버/DB 정보, 주요 배치,
  인터페이스, 운영 정보, 관련 문서 각 항목에 도달할 수 있다.
- **SC-006**: 신규 사용자가 별도 교육 없이 5개 주요 화면(Dashboard,
  코딩자동화, 담당자 찾기, 업무도우미, 모니터링)을 90% 이상의
  성공률로 스스로 찾아 이동할 수 있다.
- **SC-007**: 사용자는 모니터링 화면에서 비정상 상태 항목을 화면
  진입 즉시 시각적으로 구분해 인지할 수 있다.

## Assumptions

- **화면 간 이동 구조**: 5개 주요 화면은 공통 헤더/사이드바 등
  일관된 내비게이션 구조를 통해 서로 연결된다고 가정한다(Constitution
  원칙 IV: 컴포넌트 기반 설계).
- **사용자 권한**: V1에서는 모든 사내 임직원이 5개 화면 모두에 동일한
  수준으로 접근할 수 있다고 가정하며, 화면/기능별 세분화된 권한 관리는
  범위에 포함하지 않는다(V2 이후 검토, Constitution 원칙 VIII).
- **디자인 소스**: 각 화면의 시각적 디자인은 사용자가 제공한 Figma
  레퍼런스(Dashboard, 코딩자동화, 담당자 찾기, 업무도우미, 모니터링
  각 1건)를 Source of Truth로 하며, 실제 구현 시 Figma MCP를 통해
  참조한다(Constitution 원칙 III).
- **Dashboard의 "자주 사용하는" 판단 기준**: V1에서는 사용자별 실사용
  이력 추적 없이 Mock Data 기반의 고정/추천 목록으로 "자주 사용하는"
  항목을 표시한다고 가정한다. 실제 사용 이력 기반 개인화는 이후
  단계에서 검토한다.
- **업무도우미 대상 시스템 범위**: V1에서는 업무 시스템 예시로
  DM관리시스템, 정보보호포탈, 그룹공동영업, 동의및점검 4건을
  제공하며, 상단 선택박스로 시스템을 전환할 수 있다.
- **AI 기능의 범위**: 담당자 찾기의 Mock Response와 업무도우미의 향후
  AI Chat 연결 구조는 V1에서 UI/데이터 구조까지만 준비하며, 실제
  LLM/RAG/Agent/MCP 연동은 구현하지 않는다(Constitution 원칙 VI).
