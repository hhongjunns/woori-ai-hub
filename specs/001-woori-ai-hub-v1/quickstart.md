# Quickstart: Woori AI Hub V1 웹 서비스 검증

이 문서는 구현 완료 후 spec.md의 Acceptance Scenarios를 수동으로
검증하기 위한 가이드다(연구 결과 §3: V1은 자동화 테스트를 필수로
도입하지 않음). 각 항목의 상세 기대 동작은 `spec.md`를 참조한다.

## 사전 준비

```bash
npm install
npm run dev
```

브라우저에서 `http://localhost:3000`에 접속한다.

## 검증 시나리오

### 0. 진입 라우팅

- `/` 접속 시 `/dashboard`로 이동하는지 확인 (research.md §7)

### 1. Dashboard (`/dashboard`) — spec.md User Story 1

- 주요 AI 서비스 목록이 화면 진입 즉시(추가 조작 없이) 보이는지 확인 (SC-001)
- 자주 사용하는 업무도우미/개발자동화 도구 바로가기가 노출되는지 확인
- 바로가기 클릭 시 2회 이하 클릭으로 해당 화면에 도달하는지 확인 (SC-002)
- AI 서비스 카드 클릭 시 해당 화면으로 이동하는지 확인

### 2. 업무도우미 (`/work-assistant`) — spec.md User Story 2

- 업무 시스템 목록에서 "DM관리시스템"을 선택하면 상세 화면
  (`/work-assistant/[systemId]`)으로 이동하는지 확인
- 담당자/솔루션 정보/서버·DB 정보/주요 배치/인터페이스/운영 정보/관련
  문서 각 항목을 3회 이하 클릭/이동으로 조회할 수 있는지 확인 (SC-005)
- 지식그래프가 노드/엣지 형태로 렌더링되고 확대/축소가 동작하는지 확인
- 특정 노드를 클릭하면 해당 항목의 상세 정보가 별도 패널에 표시되는지
  확인

### 3. 코딩자동화 (`/coding-automation`) — spec.md User Story 3

- 제공되는 모든 도구의 이름/설명/상태가 화면 전환 없이 확인되는지
  확인 (SC-003)
- 도구를 클릭하면 추가 정보/상세 화면으로 이동하는지 확인

### 4. 담당자 찾기 (`/contact-finder`) — spec.md User Story 4

- 질문을 입력하고 제출하면 화면 전환 없이 Mock 답변이 채팅 메시지로
  추가되는지 확인 (SC-004)
- 두 번째 질문을 제출했을 때 이전 질문/답변이 사라지지 않고 대화
  이력에 함께 남아있는지 확인
- 빈 질문 제출 시 안내 메시지가 표시되는지 확인

### 5. 모니터링 (`/monitoring`) — spec.md User Story 5

- AI 서비스/업무도우미별 가동 상태가 표시되는지 확인
- 비정상 상태 항목이 화면 진입 즉시 시각적으로 구분되는지 확인 (SC-007)

## 완료 기준

위 시나리오가 모두 기대대로 동작하고, 각 화면의 레이아웃/컴포넌트/
타이포그래피/색상/간격이 해당 Figma 레퍼런스와 일치하면 V1 구현이
완료된 것으로 간주한다(Constitution 원칙 III).
